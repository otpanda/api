# Unmounted generated TOTP read contract

This module is not wired into the Worker, browser application, identity runtime or any client. It creates no account, key, seed or source. Production authentication remains disabled. It uses the existing encrypted seed generator with synthetic test seeds only.

A future authenticated web client can request one entry using GET /v1/manage/totp-code?entry=ENTRY. The only accepted credential is a current web device-session access handle from the existing authentication adapter. Owner, time, seed and automation parameters are not accepted. Exact existing app/API origins and no-store CORS rules apply, without credentialed cookies or new origins. Unknown and unshared entries both return404.

The server converts its trusted millisecond clock into Unix seconds for generation and checks the validity interval again after asynchronous generation. A rollover returns generic503 rather than an expired code. Session identity/device/generation is checked again after generation; existing generator checks sharing and unchanged seed state before release. Output is explicitly limited to entryId, code, period, validFrom and validUntil, with second-based intervals. No seed/envelope/source fields are returned or logged. Sixty requests per trusted ingress key per minute is a provisional conservative development default, not a global availability guarantee.

Tests cover RFC6238 synthetic output, a real internal device-session handle, session/seed/share revocation races, exact query/CORS, refresh/automation/native credential rejection, rate denial and clock rollover. This is read-only HTTP boundary evidence, not enrolled-user availability, browser integration, seed import UI, native/automation support or activation clearance. Seed provisioning, secret custody and real-account verification remain separate unfinished work.

Review follow-up: preflight validates the same single-entry query as GET, and Retry-After is exposed to the allowed app origin. Identifier validation covers the generator contract (nonempty string, at most 256 characters), with additional HTTP-only length/control-character limits before rate accounting. The provisional ingress-key rate limit runs before authentication, so clients sharing an ingress key share its budget. It is not per-account abuse protection.

The local `tool/totp-browser-check.mjs` probe uses Chromium at the exact app/API origins mapped to a local HTTPS server backed by workerd and D1. It proves the actual queried OPTIONS204 followed by Authorization GET200 with encrypted synthetic RFC6238 seed generation and browser-readable Retry-After on429. Its session authenticator is explicitly synthetic; the separate unit integration test uses actual account/passkey/device-session services and an actually minted EntryTokenStore automation credential. No user browser profile or production route is involved. This is a local, non-CI proof. To run from the repository root, install Playwright with its Chromium browser, set OTPANDA_TEST_TLS_KEY and OTPANDA_TEST_TLS_CERT to local test-only PEM files, and run node tool/totp-browser-check.mjs. OTPANDA_PLAYWRIGHT_MODULE can point to an existing Playwright module; OTPANDA_TEST_PORT defaults to8443 and can be changed. The browser accepts the local test certificate; DNS mapping stays local. The fixed clock means this proves the rate-denial response, not wall-clock budget expiry.

Product exposure is intentionally unchanged from EntryTotpGenerator: active selected-entry recipients can view generated codes without a new step-up; automation still requires its separate permission, and seeds are never released. Mounting this route would make that existing core permission reachable over authenticated web HTTP. That activation remains outside this increment and requires a separate review of the browser-session exposure and key custody.
