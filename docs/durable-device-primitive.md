# Inactive durable-device proof primitive

Based on API main be2afe3; migration0021 is additive. No HTTP route imports these modules. It returns a proof, never a session, account reset, credential deletion or other effect. There is no attestation and readiness.platformVerified is false.

Enrollment caller must provide verifier-produced fresh action-bound strong proof, never a body-supplied assertion. The bound action commits to public JWK. Possession is independently challenged. Lost confirmation can be reconciled only under fresh strong enrollment authority and possession using the same public key identifier. Revoked SPKI is a tombstone and cannot be revived. Existing nonrevoked SPKI can be enrolled into a current generation only with fresh proof. Missing-device replacement, cross-account native key use, multi-account identity display and any new restore workflow are undefined, not implicit permissions.

Browser-binding secret and challenge token are both required. Matching finish consumes challenge before signature verification; invalid proof burns it. Final key insert/update rechecks account generation and credential/key revocation. Returned action digest/purpose/generation/key must still be checked transactionally against the eventual caller effect and current authority. No caller integration is supplied here. Proof reuse cannot cause an effect because none is wired; mounting must also enforce effect-specific single-use authorization.

Limits:32 unexpired enrollment challenges per owner,8 nonenrollment challenges per key,20 current-generation nonrevoked keys. Same-key refresh excludes itself. Each issue removes at most64 expired rows; sweepExpired is separately callable for bounded scheduled maintenance if traffic cannot keep up. These internal limits do not replace public ingress abuse protection. Known key ID can still exhaust that key's cap, not all owner key capacity.

Tests: npm run check/build; node tool/durable-device-d1-check.mjs for actual local workerd D1. SQLite tests exercise current migrations, single-use, binding, bad-signature burn, expiry, generation/revocation/credential races, key limits, duplicate SPKI reconciliation, revoked tombstone and bounded cleanup. Local workerd tool applies current migrations and checks cryptographic enrollment, duplicate reconciliation, parallel finish one winner, expiry and revoked enrollment denial. It is not a production D1 claim.

Shared test/device-proof-vector.json contains public SPKI/message/DER/P1363 fixture executed by the server verifier and inactive native JVM test runner. No private key included. Android hardware/lifecycle policy, direct-sign denial, OS credential fallback, cloud/device backup and release package/signing identity remain distinct gates. Ordinary generated host does not include native source.
