# PKCE browser exchange storage, not live restore

BrowserExchangeService is an internal unmounted store for short-lived, one-use restoration codes. It accepts only the canonical app redirect https://otpanda.github.io/app/ and web-kind active devices. SHA256 PKCE uses a43-128 character verifier; only its challenge and code digest are stored. Wrong verifier/secret/redirect does not consume a legitimate code. A correctly bound code consumes once before active-device/credential/security-generation checks and mints only a five-minute access handle. Expiry is rechecked after asynchronous handle generation. No refresh secret is returned here.

This does not authorize a caller to mint by supplying a device ID. The HTTP boundary must first verify the actual API-host first-party refresh cookie, rotate it, enforce exact approved Origin where applicable, rate-limit and derive the device server-side. A request body is never trusted proof. Redirect state/verifier remain in tab-scoped storage and all callback URL data must be removed before any third-party content runs. Top-level restoration and browser-cookie restrictions need real browser tests. Extension and native clients cannot use this browser store. No endpoint is mounted or auth enabled by this increment.

Still required: trusted ceremony/login binding, CSRF, PKCE state lifecycle, strict callback input handling, verified-email delivery and actual signup/session integration, sensitive effects conditioned on current generation, quotas/cleanup and readiness warnings. Synthetic tests are not a browser or native device assurance claim.
